## 1. Создание пользователя и группы

**Цель:** проверить наличие пользователя `student2` и группы `developers`, а также убедиться, что пользователь входит в эту группу.

Для проверки использовались команды:

```bash
getent passwd student2
getent group developers
id student2
```

Результат проверки:

```text
student2:x:1001:1002:Baiel,124,911,199:/home/student2:/bin/bash
developers:x:1001:student2
uid=1001(student2) gid=1002(student2) groups=1002(student2),1001(developers)
```

**Результат:** пользователь `student2` существует и входит в группу `developers`. Основная группа пользователя — `student2`, дополнительная группа — `developers`.

## 2. Настройка общего каталога

**Цель:** проверить владельца, группу и права доступа общего каталога `/srv/shared`.

Команды проверки:

```bash
ls -ld /srv/shared
stat -c '%A | %a | владелец=%U | группа=%G' /srv/shared
```

Результат:

```text
drwxrwsr-x 2 root developers 4096 Sep 22 12:52 /srv/shared
drwxrwsr-x | 2775 | владелец=root | группа=developers
```

Каталог `/srv/shared` принадлежит пользователю `root` и группе `developers`.

Права доступа каталога — `2775` (`drwxrwsr-x`):

- **Владелец `root`:** чтение, запись и доступ к каталогу.
- **Группа `developers`:** чтение, запись и доступ к каталогу.
- **Остальные пользователи:** чтение и доступ к каталогу, без права записи.
- **Бит SGID:** новые файлы и каталоги наследуют группу `developers`.

**Результат:** участники группы `developers` могут создавать файлы в общем каталоге, а остальные пользователи не имеют права записи в него.

## 3. Проверка прав доступа

**Цель:** проверить, может ли пользователь удалить файл, созданный другим пользователем.

Сначала пользователь `student2` создал тестовый файл:

```bash
sudo -u student2 touch /srv/shared/pr1_delete_test.txt
```

Затем от имени пользователя `userkutman` была выполнена попытка удаления:

```bash
rm -f /srv/shared/pr1_delete_test.txt
echo "Код удаления: $?"
```

Результат:

```text
rm: cannot remove '/srv/shared/pr1_delete_test.txt': Permission denied
Код удаления: 1
```

Проверка показала, что файл остался в каталоге:

```bash
ls -l /srv/shared/pr1_delete_test.txt
```

Результат:

```text
-rw-rw-r-- 1 student2 developers 0 Oct 26 21:21 /srv/shared/pr1_delete_test.txt
```

После проверки файл был удалён пользователем `student2`:

```bash
sudo -u student2 rm /srv/shared/pr1_delete_test.txt
```

Команда выполнилась успешно.

**Объяснение:** пользователь `userkutman` не имеет права записи в каталог `/srv/shared`, поэтому не может удалить из него файл обычной командой `rm`. Пользователь `student2` входит в группу `developers`, которой разрешена запись в каталог.

**Результат:** проверка подтвердила, что права доступа к каталогу работают согласно настройкам.

## 4. Разница между `su` и `sudo`

`su` (Substitute User) позволяет переключиться на другого пользователя. Если имя пользователя не указано, обычно выполняется переключение на `root`.

Пример:

```bash
su - student2
```

Команда открывает оболочку пользователя `student2` после успешной аутентификации.

`sudo` позволяет выполнить отдельную команду с повышенными привилегиями, если пользователь имеет соответствующие разрешения.

Пример:

```bash
sudo apt update
```

**Основные различия:**

- `su` используется для переключения на другого пользователя.
- `sudo` используется для выполнения отдельных команд с повышенными привилегиями.
- `sudo` позволяет выполнять административные задачи, не работая постоянно от имени `root`.

---

## 5. Почему вход `root` по умолчанию заблокирован

В Ubuntu учётная запись `root` обычно не имеет установленного пароля для прямого входа. Для выполнения административных задач рекомендуется использовать `sudo`.

Это повышает безопасность системы:

- уменьшает риск случайного повреждения системы;
- позволяет выполнять административные команды только при необходимости;
- помогает связывать выполнение команд с конкретной учётной записью;
- снижает необходимость постоянно работать с максимальными привилегиями.

**Вывод:** использование `sudo` позволяет выполнять административные задачи, сохраняя обычную работу под своей учётной записью.

## 6. Настройка `.bashrc`

**Цель:** настроить два алиаса и переменную окружения, а затем проверить их работу в новом интерактивном сеансе Bash.

В файле `~/.bashrc` настроены алиасы:

```bash
alias ll='ls -lah'
alias c='clear'
```

Также настроена переменная окружения:

```bash
export MY_HOMEWORK="prNN"
```

Назначение настроек:

- `ll` — выводит подробный список файлов, включая скрытые, с размерами в удобном формате.
- `c` — очищает экран терминала.
- `MY_HOMEWORK` — пользовательская переменная окружения со значением `prNN`.

Для проверки использовалась команда:

```bash
bash -ic 'type ll; type c; echo "$MY_HOMEWORK"'
```

Результат:

```text
ll is aliased to `ls -lah'
c is aliased to `clear'
prNN
```

**Результат:** оба алиаса распознаются оболочкой, а переменная окружения выводит заданное значение. Следовательно, настройки `.bashrc` работают в новом интерактивном сеансе Bash.
